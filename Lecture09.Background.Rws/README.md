# Лекция 09 — RecurrentWorkerService (RWS)

Несколько экземпляров **VideoService**, внутри которых по расписанию
работают три воркера RWS в распределённом режиме. Экземпляры запускаются и
останавливаются руками в отдельных консолях, в любой момент. Запуски они
согласуют через кластер **etcd** из трёх узлов, без выбора лидера: каждую
итерацию выполняет ровно один экземпляр.

## Воркеры

| Воркер | Расписание | Что делает |
|---|---|---|
| `UploadsPollingWorker` | Recurrent, раз в 3 секунды, режим multi-iteration (окно 1 секунда) | опрашивает таблицу роликов в статусе `uploaded` и переводит их в `validated` (подход "статус в БД") |
| `TrendingWorker` | Cron, `* * * * *` | раз в минуту пересчитывает популярные ролики |
| `TranscodingQueueWorker` | Workload, от 1 до 16 секунд | забирает из очереди перекодирования пачку до 10 роликов; чем больше работы, тем чаще запуски |

Полезная нагрузка — сообщения в логе и `Task.Delay`. Расписания заданы в
`Program.cs` (`SetPeriod`, `SetCronExpression`, `SetRange`, `SetStrategies`).

Нагрузку на очередь перекодирования изображает профиль в
`TranscodingQueueWorker`: фазы по 20 секунд, в каждой — процент заполнения
пачки (`0, 0, 30, 100, 100, 60, 10`). Фаза вычисляется из текущего времени,
поэтому на всех узлах одна и та же.

## Концепции

- **Итерации не перекрываются** — следующий запуск начинается только после
  завершения текущего. При ошибке итерация повторяется через
  `RetryOnFailDelay`.
- **Recurrent** — запуск раз в `Period`, независимо от длительности
  итерации.
- **Cron** — пять полей, минимальный шаг — минута.
- **Workload** — воркер возвращает `Workload` от 0 до 255 (доля выполненной
  работы, здесь `Workload.FromDoneItems(взято, 10)`), а интервал до
  следующего запуска вычисляется из предыдущего интервала по стратегиям:

  | Workload | Действие | Смысл |
  |---|---|---|
  | 0–62 | `Multiply 2` | почти нет работы — опрашиваем вдвое реже |
  | 63–190 (от 25%) | `Subtract 4 с` | средняя нагрузка — немного чаще |
  | 191–254 (от 75%) | `Divide 2` | много работы — вдвое чаще |
  | 255 | `Set 1 с` | пачка заполнена целиком — сразу минимальный интервал |

  Результат всегда ограничен диапазоном `PeriodFrom`–`PeriodTo` (1–16 с).
- **Распределённый режим** (`AddDistributedWorkers` + `AddEtcdPersistence`)
  — узлы равноправны, id узла RWS генерирует сам (печатается при старте).
  Перед каждой итерацией узел берёт блокировку в etcd, проверяет, не
  выполнена ли уже эта итерация, выполняет её и записывает ключ успеха:
  - у Recurrent и Cron номер итерации вычисляется из времени, поэтому на всех
    узлах одинаков (часы узлов должны быть синхронизированы по NTP), а ключ
    `video-service/uploads-polling/{N}/Success` не даёт выполнить итерацию
    дважды;
  - у Workload последняя нагрузка и интервал хранятся в ключе
    `video-service/transcoding-queue/WorkLoad`, поэтому интервал общий для
    всего кластера.
- **Multi-iteration** — `uploads-polling` зарегистрирован с третьим
  параметром `SetMultiIterationOnNodeMaxDuration`. В этом режиме узел берёт
  блокировку один раз и держит её до конца окна (здесь 1 секунда), выполняя
  итерации подряд локально, без похода в etcd за блокировкой на каждую. Потом
  отпускает блокировку, и её может забрать любой узел. Режим нужен для очень
  частых итераций, например `SetPeriod(TimeSpan.Zero)` — "так часто, как
  получится": обычный режим упирается в задержку до etcd. С периодом 3
  секунды и окном 1 секунда узел за один захват блокировки успевает одну
  итерацию; увеличьте окно до 10 секунд — один узел будет выполнять несколько
  итераций подряд, потом работа перейдёт к другому. В опубликованном пакете
  1.0.1-alpha.1 multi-iteration есть только у Recurrent-воркеров.
- **Heartbeat** — каждый узел держит в etcd lease с TTL 7 секунд и продлевает
  его каждую секунду. Блокировки узла привязаны к lease: если узел упал,
  через 7 секунд блокировки и ключи исчезают сами.

## 1. Запуск etcd

```bash
docker compose up -d
```

Три узла etcd на `localhost:23791`, `23792`, `23793`. Проверить кластер:

```bash
docker exec lecture09-etcd1 etcdctl endpoint health --cluster
```

## 2. Запуск узлов

Каждый узел в своей консоли:

```bash
cd Lecture09.Background.Rws.VideoService
dotnet run
```

Запустите так же ещё два узла. При старте узел печатает свой id и `pid`.

## Остановка

```bash
docker compose down
```
