# Лекция 07 — WebSocket

Минимальный пример на WebSocket: глобальный анонимный чат. Сервер выдаёт
каждому подключению никнейм вида `Аноним 1`, `Аноним 2` и рассылает
каждое сообщение всем подключённым.

## Концепции

- **Upgrade** — WebSocket начинается как обычный `GET /chat/ws`, после
  чего соединение переключается на свой протокол и становится
  двусторонним: и клиент, и сервер могут отправлять сообщения в любой
  момент. Смотрите вкладку Network → `ws` → Messages в DevTools.
- **История + подписка** — страница сначала забирает последние сообщения
  обычным `GET /chat/messages`, а потом подписывается на новые по
  WebSocket. Между этими двумя шагами есть маленькое окно, в которое
  сообщение может потеряться. Хороший вопрос для обсуждения: как это
  исправить? (подсказка: сначала подписаться, потом загрузить историю и
  убрать дубликаты по `Id`).
- **Контракт** — WebSocket передаёт просто текст или байты, формат
  сообщений придумываем сами (`Api/Chat/Contract`):
  - клиент → сервер: `SendMessageRequest` — `{"text":"..."}`;
  - сервер → клиент: `ChatEvent` — `{"type":"welcome","nickname":"Аноним 3"}`
    сразу после подключения или `{"type":"message","message":{...}}` для
    каждого нового сообщения.
- **Состояние в контроллере** — экземпляр контроллера живёт один запрос,
  поэтому список сокетов и история лежат в `static` полях. Но WebSocket-
  запрос живёт столько же, сколько само соединение, поэтому метод
  `Connect` крутит цикл чтения, пока клиент не отключится.
- **Одна отправка за раз** — у `WebSocket` нельзя вызывать `SendAsync`
  параллельно, а сообщения от разных клиентов приходят одновременно.
  Поэтому рассылка идёт под `SemaphoreSlim`.

## Запуск

```bash
cd Lecture07.Realtime.WebSockets.ChatService
dotnet run
```

- Страница: [http://localhost:5071](http://localhost:5071)
- Swagger: [http://localhost:5071/swagger](http://localhost:5071/swagger)

Откройте страницу в нескольких вкладках (или с нескольких устройств в
одной сети) и пишите.
