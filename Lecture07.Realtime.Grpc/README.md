# Лекция 07 — gRPC bidirectional streaming

Две службы обмениваются сообщениями через один долгоживущий gRPC-вызов, в
котором данные идут **в обе стороны одновременно**.

- **FeederService** (`Lecture07.Realtime.Grpc.FeederService`) — умная
  кормушка. Сама подключается к приюту и раз в секунду отправляет
  телеметрию: сколько кот съел и сколько корма осталось.
- **ShelterService** (`Lecture07.Realtime.Grpc.ShelterService`) — центр
  управления приютом. По тому же вызову раз в 3 секунды отправляет
  кормушке команды: досыпать до полной, если корма меньше 60 г, иначе
  выдать лакомство 10 г.

## Концепции

- **Четыре вида вызовов gRPC** — unary (запрос → ответ, как в лекции 02),
  server streaming (запрос → поток ответов), client streaming (поток
  запросов → ответ) и **bidirectional streaming** — поток в обе стороны:

  ```proto
  rpc Connect (stream FeederTelemetry) returns (stream FeederCommand);
  ```

- **Один вызов — два независимых потока** — клиент начинает вызов и
  получает `RequestStream` (писать) и `ResponseStream` (читать). Каждая
  сторона одновременно крутит два цикла: один пишет, другой читает. Они
  не ждут друг друга: кормушка шлёт телеметрию раз в секунду, приют шлёт
  команды раз в 3 секунды, и это не "запрос-ответ".
- **Поверх HTTP/2** — вызов — это один HTTP/2-стрим, который живёт, пока
  кормушка подключена. Поэтому в `appsettings.json` приюта Kestrel
  работает только по HTTP/2.
- **Инициатор всегда клиент** — сервер не может сам подключиться к
  кормушке, зато после подключения может слать ей сообщения когда угодно.
  Поэтому кормушка — клиент, а приют — сервер, хотя команды идут от
  приюта.
- **Завершение** — кормушка при остановке вызывает
  `RequestStream.CompleteAsync()`: у приюта заканчивается цикл чтения, он
  завершает вызов, и у кормушки заканчивается цикл чтения команд.
- **Переподключение** — если приют ещё не запущен или перезапустился,
  кормушка ловит `RpcException` и через 2 секунды открывает новый поток.
- **Много клиентов** — `Connect` вызывается отдельно для каждой кормушки,
  у каждой свой поток и свои команды.

## 1. Запуск приюта

```bash
cd Lecture07.Realtime.Grpc.ShelterService
dotnet run
```

Слушает `http://localhost:5073` (HTTP/2).

## 2. Запуск кормушек

```bash
cd Lecture07.Realtime.Grpc.FeederService
dotnet run
```

Каждая кормушка в своей консоли, со своим id и котом:

```bash
dotnet run -- --Feeder:FeederId=feeder-2 --Feeder:CatName=Мурка
dotnet run -- --Feeder:FeederId=feeder-3 --Feeder:CatName=Рыжик
```
