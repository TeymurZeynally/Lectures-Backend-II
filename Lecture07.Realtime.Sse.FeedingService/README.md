# Лекция 07 — Server-Sent Events

Минимальный пример на SSE: в приюте стоят "умные" кормушки, которые
сообщают, сколько корма осталось. Страница показывает их состояние и
обновляется сама, без перезагрузки и без опроса сервера по таймеру.

## Концепции

- **SSE — это обычный HTTP** — клиент делает `GET /feeders/stream`, а
  сервер не завершает ответ: отдаёт `Content-Type: text/event-stream` и
  время от времени дописывает в него события. Каждое событие — несколько
  строк `поле: значение` и пустая строка в конце:

  ```
  event: feeder-updated
  data: {"id":1,"catName":"Барсик","foodGrams":150,...}

  ```

  Формат написан руками в `FeedersController.Stream`, чтобы его было
  видно. В .NET 10 то же самое делает `TypedResults.ServerSentEvents`.
- **Только сервер → клиент** — SSE односторонний. Когда пользователь
  нажимает "Досыпать", страница отправляет обычный `POST
  /feeders/{id}/refill`, а результат прилетает всем открытым вкладкам
  через поток.
- **EventSource** — встроенный в браузер клиент SSE (`wwwroot/app.js`).
  Сам переподключается, если соединение оборвалось. Поэтому сервер при
  каждом подключении первым делом отдаёт текущее состояние всех кормушек,
  а потом только изменения — после переподключения страница не отстаёт.
- **Рассылка** — `FeedersService` заводит на каждое подключение свой
  `Channel` и пишет каждое обновление во все каналы. `FeedingSimulator`
  раз в секунду "съедает" корм из случайной кормушки.

## Запуск

```bash
cd Lecture07.Realtime.Sse.FeedingService
dotnet run
```

- Страница: [http://localhost:5070](http://localhost:5070)
- Swagger: [http://localhost:5070/swagger](http://localhost:5070/swagger)

Откройте страницу в двух вкладках и нажмите "Досыпать" в одной из них —
вторая обновится сама.

Сам поток можно посмотреть без браузера:

```bash
curl -N http://localhost:5070/feeders/stream
```

Остановите сервер (Ctrl+C) — на странице появится "переподключение...".
Запустите снова — EventSource подключится сам.
